# Lexio M1 — Phase 2 상세 계획

> 같은 물리 테이블에 앉은 세 명만 하나의 수동매치로 묶고, 각 테이블의 카운트다운과 게임 상태를 독립적으로 운영한다.

상태: 핵심 구현·결정적 격리 테스트·실제 3인 한 판 완료 — 동시 테이블 검증 대기

## 1. 목표

`LexioTableRegistry`가 관리하는 `table01`~`table03`의 착석자를 기준으로 테이블별 게임 세션을 만든다. 같은 테이블의 세 좌석이 모두 채워진 상태가 3초 동안 유지되면 그 세 명만 게임을 시작하며, 누군가 일어서면 해당 테이블의 카운트다운만 취소한다.

## 2. 시작 상태

- map01에는 테이블 3개와 테이블별 좌석 3개가 있다.
- 서버 좌석 레지스트리는 `tableId + seatIndex`와 플레이어 소유권을 관리한다.
- 같은 파란 의자 테이블에 실제 플레이어 3명이 동시에 착석하는 것까지 사용자 확인이 완료됐다.
- 기존 `LexioSessionCoordinator`와 `LexioGameSession`은 맵 전체에서 하나만 존재한다.
- map01의 기존 전역 카운트다운은 Phase 1에서 차단된 상태다.

## 3. 범위

### 포함

- 테이블별 대기·카운트다운·게임 중·종료 상태
- 같은 테이블 3명에 대한 독립적인 3초 카운트다운
- 착석 해제 시 해당 테이블 카운트다운 취소
- 테이블별 `LexioGameSession` 소유권과 플레이어 좌석 매핑
- 제출·패스·스냅샷·종료·재경기 요청의 테이블 라우팅
- 두 테이블 동시 실행 시 상태 격리

### 제외

- 자동매치 대기열과 빈 테이블 자동 배정 — Phase 3
- 재접속 복구와 관전자 기능 — M2
- 세 테이블 동시 실제 사용자 부하 검증 — Phase 4

## 4. 권한과 상태 모델

서버의 테이블별 런타임 상태는 다음 정보를 가진다.

| 필드 | 의미 |
|---|---|
| `tableId` | `table01`~`table03` |
| `phase` | `Waiting`, `Countdown`, `Playing`, `Finished` |
| `countdownRemaining` | 해당 테이블에만 적용되는 남은 시간 |
| `countdownGeneration` | 취소된 타이머의 지연 완료를 무효화하는 세대 값 |
| `userIdBySeat` | 물리 좌석 1~3과 게임 좌석의 동일 매핑 |
| `sessionEntity/sessionComponent` | 해당 테이블 전용 게임 세션 |
| `bridgeByUserId` | 해당 세션 요청과 응답을 받을 플레이어 브리지 |

필수 불변 조건:

1. 플레이어는 한 번에 하나의 테이블 세션에만 속한다.
2. 카운트다운 완료 직전에도 같은 세 명이 같은 좌석에 앉아 있어야 한다.
3. 한 테이블의 착석·일어서기·게임 종료는 다른 테이블 상태를 바꾸지 않는다.
4. 클라이언트가 보낸 테이블 ID를 신뢰하지 않고 서버 좌석 레지스트리에서 소속을 다시 확인한다.
5. 모든 게임 요청은 요청자의 현재 테이블 세션으로만 전달한다.

## 5. 구현 체크리스트

### ✅ 1. 테이블별 코디네이터와 세션 수명 분리

- map01 호스트가 세 개의 테이블 런타임 레코드를 생성한다.
- 기존 단일 세션 로직을 테이블 ID를 받는 관리 계층으로 감싼다.
- 각 테이블에 독립 `LexioGameSession` 컴포넌트 또는 전용 세션 엔티티를 연결한다.
- 기존 자동 플레이어 등록을 물리 좌석이 확정된 플레이어 등록으로 변경한다.
- 플레이어 브리지에 서버가 결정한 `tableId`와 게임 좌석을 바인딩한다.

### ✅ 2. 테이블별 3초 카운트다운 연결

- 좌석 예약·해제 후 레지스트리가 해당 테이블의 인원 변화를 코디네이터에 알린다.
- 정확히 세 좌석이 채워지면 그 테이블만 3초 카운트다운을 시작한다.
- 3초 동안 좌석 소유자 구성이 바뀌면 즉시 취소한다.
- 카운트다운 완료 시 좌석 구성 재검증 후 한 번만 게임을 시작한다.
- 다른 테이블의 카운트다운과 로그가 영향을 받지 않게 한다.

### ✅ 3. 게임 요청과 스냅샷을 테이블별로 라우팅

- 준비·제출·패스·종료 결정·재경기 요청에서 요청자의 서버 좌석을 조회한다.
- 요청을 해당 테이블의 세션에만 전달한다.
- 공개 스냅샷과 개인 패는 같은 테이블 참가자에게만 전송한다.
- UI의 좌석 이름·카운트다운·게임 상태는 로컬 플레이어의 테이블 스냅샷만 표시한다.
- 일어서기와 맵 이탈 시 Waiting/Countdown에서는 즉시 세션 소속을 해제한다.

### ⬜ 4. 독립 세션 검증

- table01 카운트다운 중 table02 인원 변화가 table01을 취소하지 않는지 테스트한다.
- table01과 table02의 서로 다른 패·턴·제출 목록·승자를 확인한다.
- 한 테이블의 제출/패스 요청이 다른 테이블의 상태 버전을 바꾸지 않는지 테스트한다.
- 게임 종료 후 해당 테이블 좌석과 세션만 정리되는지 확인한다.
- 빌드 로그, 런타임 로그, 다중 클라이언트 사용자 테스트를 수행한다.

## 7. 구현 순서

1. 기존 코디네이터·게임 세션·브리지의 단일 세션 가정을 목록화한다.
2. 테이블별 세션 생성과 플레이어 바인딩을 구현한다.
3. 좌석 레지스트리에서 테이블별 카운트다운을 연결한다.
4. 제출·패스·스냅샷·종료 요청을 테이블별로 라우팅한다.
5. 단일 테이블 3명 게임을 먼저 검증한다.
6. 두 테이블 동시 상태 격리를 검증한다.

## 8. 완료 기준

- 같은 테이블 세 좌석이 채워지면 3초 카운트다운이 시작된다.
- 카운트다운 중 한 명이 일어서면 그 테이블만 취소된다.
- 서로 다른 테이블에 나뉘어 앉은 세 명으로는 시작되지 않는다.
- 카운트다운 완료 후 해당 테이블 세 명만 게임 UI와 패를 받는다.
- 제출·패스·턴·종료·재경기가 다른 테이블에 영향을 주지 않는다.
- 빌드 및 런타임 오류가 없다.

### 자동 검증 기록 — 2026-09-04

- 독립된 두 `LexioGameSession`에서 서로 다른 패·선 플레이어를 구성했다.
- 한 세션의 제출이 다른 세션의 상태 버전·턴·패 수를 변경하지 않음을 확인했다.
- 한 세션의 종료와 초기화가 다른 세션의 진행 상태를 변경하지 않음을 확인했다.
- Maker 런타임 결과: `LexioGameSessionTests` 63개 통과, 실패 0개.
- 실제 3인 수동 매칭 한 판 완주는 사용자 검증을 통과했다. 이 과정에서 발견된 닉네임 차례 표시와 공개 제출 카드 배치 문제는 수정했다.
- 실제 두 테이블 동시 진행에 필요한 6인 격리 검증은 계속 대기 상태다.

## 9. 사용자 검증 경계

AI는 서버 상태 테스트와 단일 클라이언트 런타임 검증을 수행한다. 실제 같은 테이블 3인 시작과 두 테이블 동시 게임은 각각 3명과 6명의 다중 클라이언트가 필요하므로 사용자 확인 전에는 해당 검증 항목을 🟡로 유지한다.

## 10. Phase 3 인계

자동매치는 빈 테이블을 예약한 뒤 세 플레이어를 이 Phase의 정상 좌석 예약 경로로 앉힌다. 자동매치 전용 게임 시작 우회 경로를 만들지 않고, 수동매치와 동일한 테이블별 카운트다운·세션 생성 흐름을 재사용한다.
