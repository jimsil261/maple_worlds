# 메이플 렉시오 - 기술 포트폴리오

김재렬 | 개인 프로젝트 | 2026.10-11 | MapleStory Worlds · mLua

## 결과와 역할

2026년 11월 21일 공개 베타 출시. 이동형 보드게임 카페 시제품을 PC 정적 UI 카드 게임으로 개편했다. 3·4·5인 각 12장, 공개방·비밀번호·빠른 매칭, 정산·재경기, 채팅과 아바타, 이탈·AI 대행·복귀를 연결했다.

제작자는 게임 방향, 기능 우선순위, UI 피드백, 실제 플레이 확인과 출시를 담당했다. AI 코딩 도구는 설계 정리, 코드 작성·수정, 회귀 검사·프로브, 문서화와 일부 이미지에 활용했다. AI가 작성한 코드를 독립적으로 검증해야 한다는 점도 출시 과정에서 확인했다.

## 구조

UI → PlayerBridge / ManualTestControls → TableRegistry → SessionCoordinator → GameSession → Rules. 이 흐름은 책임 관계를 단순화한 것으로 모든 요청이 동일 호출 순서를 지나는 것은 아니다.

- Rules: 조합의 유효성, 강도, 점수 규칙.
- GameSession: 손패, 차례, 패스·트릭, 한 판의 정산.
- TableRegistry: 방 생성·좌석 소유권·대기열·빈 방 회수. 같은 인원 방도 동적으로 생성한다.
- SessionCoordinator: 준비·카운트다운·15초 턴·AI·투표·종료/재경기 전이.
- PlayerBridge: 클라이언트 요청과 공개/개인 스냅샷 경계. 사용자·요청 ID·상태 버전 검증.
- UI: 6열 2행 카드, 아바타, 말풍선, 족보·음량 팝업. 서버 상태와 표시를 분리한다.

## 상태 정책

이탈하면 턴을 멈추고 남은 사람에게 30초 투표를 연다. 찬성은 절반 초과, 미투표는 반대다. 통과하면 AI가 대행하고 본래 소유자는 재접속 화면에서 같은 좌석으로 복귀할 수 있다. 종료 시점에 AI가 남아 있으면 정산 후 방을 닫는다. 종료 전에 사람이 돌아왔다면 만장일치로 재경기하며 점수는 이월한다. 새 방은 64점이다.

## 문제 해결

### 방 독립성과 매칭

처음에는 인원별 고정 테이블을 공유했다. 동적 호스트와 방 식별자 경계로 여러 방을 만들도록 바꾸고, 기존 방 정리가 새 방의 좌석을 해제하지 않는지 검사했다. 빠른 매칭은 기존 공개 대기방의 빈자리를 먼저 채운 뒤 남은 대기자로 새 방을 구성한다.

### AI 복귀와 종료 정책

AI가 자리를 대행하는 것과 원래 사용자의 소유권 포기를 구분했다. AI 대행 후 재접속은 허용하되, 스스로 로비로 이동하면 복귀를 포기한다. 한 판 더는 AI 투표의 과반 규칙과 분리해 전원 동의를 요구한다.

### 출시 환경의 UI·오디오

메서드 직접 호출로 팝업 Enable만 확인한 검사는 실제 가림을 놓쳤다. 출시 클라이언트에서 실제 클릭으로 재현하고 소리 팝업을 게임 HUD에서 공통 UI로 분리했다. 이후 출시본의 실제 창 표시를 확인했다. 효과음 100%에 낮은 내부 배율이 곱해지던 문제도 재생 인자 1.0 기준으로 수정했다. KickUser를 종료에 쓰면 추방 문구가 나오는 문제는 해당 처리를 제거하고 사용자 요청으로 종료 버튼을 없앴다.

## 검증과 한계

독립 Lua 검사 3,625개 단언 통과: 규칙 50 + 세션 108 + 추가 3,467. 실제 mLua 메서드를 Fengari로 실행하지만 엔진·RPC·렌더링은 대역이므로 실계정 검증의 대체물이 아니다.

Maker에서 3/4/5인 각 두 판, 270회 타이머 행동과 점수 합 유지, 동적 방 격리, 방 생성·변경·퇴장·재생성을 프로브로 확인했다. 최신 코드의 빌드/실행 오류·경고는 0이었다. 출시 클라이언트에서는 접속, 소리 설정 클릭·표시, 공식 로비 이동을 확인했다.

독립된 실제 계정 다인 게임, 실제 웹 실행, 장시간 부하와 다른 서버 인스턴스 복구는 미검증 또는 미지원이다. 플랫폼 최대 인원 설정 16은 부하 검증 결과가 아니다. 출시 이후 피드백을 바탕으로 베타를 개선할 예정이다.
