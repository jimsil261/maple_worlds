> Parent doc: `Lexio-M1-GDD.md` · 이 단계에서는 여러 테이블의 물리 배치와 좌석 상태 격리까지만 완성하고, 실제 게임 시작과 자동 매칭은 후속 단계에서 연결한다.

상태: 구현 준비 완료

## 1. 목표

map01에 테이블 3개와 테이블별 의자 3개를 배치하고 각 좌석을 `tableId + seatIndex`로 식별한다. 플레이어는 기본 상태에서 매칭에 참여하지 않으며, X 키로 가까운 물리 좌석에 앉거나 일어난다. 서로 다른 테이블의 좌석 상태는 완전히 분리한다.

## 2. 시작 상태

- map01에는 기존 단일 테이블용 의자 3개와 X 키 착석 로직이 있다.
- 서버는 착석자 3명을 전역으로 집계해 3초 카운트다운을 시작한다.
- 좌석은 의자 엔티티 이름 중심이며 테이블 소속 개념이 없다.
- UI는 착석 중에만 표시된다.

## 3. 범위와 비범위

포함:

- 서버 권한 테이블·좌석 레지스트리
- `table01`~`table03`, 각 테이블의 `seat01`~`seat03`
- map01의 테이블 3개와 의자 9개 배치
- X 키 착석·일어서기, 중복 점유 차단, 플레이어당 한 좌석 제한
- 테이블 간 착석 상태 격리와 기존 전역 3인 시작 차단

이번 단계에서 제외:

- 같은 테이블 3인 게임 시작과 세션 분리 — Phase 2
- 자동매치 버튼, 대기열, 빈 테이블 배정 — Phase 3
- 재접속·관전자·확장성과 최종 시각 폴리시 — M2 또는 Phase 4

## 4. 상태 계약

| 항목 | 규칙 |
|---|---|
| 테이블 ID | `table01`, `table02`, `table03` |
| 좌석 인덱스 | `1`, `2`, `3` |
| 테이블 엔티티 | `LexioTable01` 형식 |
| 의자 엔티티 | `LexioTable01Chair1` 형식 |
| 기본 플레이어 상태 | 테이블·좌석·매칭 모드 없음 |
| 수동 착석 상태 | `mode=manual`, `tableId`, `seatIndex`, `chairEntityName` |

서버 불변 조건:

1. 한 좌석에는 한 플레이어만 존재한다.
2. 한 플레이어는 한 좌석에만 존재한다.
3. map01에 있고 해당 의자 가까이에 있는 플레이어 요청만 허용한다.
4. 일어서기, 맵 이탈, 게임 종료 시 플레이어와 좌석 상태를 함께 해제한다.
5. 한 테이블의 인원 변화는 다른 테이블에 영향을 주지 않는다.

## 5. 구현 체크리스트

### ✅ 1. 서버 권한 테이블 레지스트리 구축

- map01 수명에 맞는 테이블 레지스트리 컴포넌트를 추가한다.
- 세 테이블과 아홉 좌석의 고정 구성을 초기화한다.
- 좌석 예약, 좌석 해제, 플레이어 전체 해제, 테이블 인원 조회, 플레이어 좌석 조회 책임을 분리한다.
- 클라이언트가 보낸 테이블 ID·좌석 번호·의자 이름을 고정 구성과 대조한다.
- 맵 이탈이나 엔티티 정리 시 남은 좌석 소유권을 해제한다.
- 예약 성공·거부·해제 지점에 진단 로그를 둔다.

### ✅ 2. 테이블 3개와 의자 9개 물리 배치

- 구현 시작 시 MapBuilder 스냅샷으로 map01의 가용 공간과 충돌물을 확인한다.
- 구분되는 세 클러스터에 테이블과 의자 3개씩을 배치한다.
- 좌표는 월드 단위로 기록하고 포탈과 주요 이동 동선을 침범하지 않게 한다.
- 기존 의자 리소스를 재사용한다. 테이블 리소스가 없으면 MSW 리소스 검색으로 검증된 RUID를 선정한다.
- `.model`은 ModelBuilder, `map01.map`은 MapBuilder로만 수정한다.
- 각 의자에 테이블 ID와 좌석 인덱스를 식별할 구성을 연결한다.

### ✅ 3. X 키 착석을 테이블 좌석 방식으로 전환

- 클라이언트는 가까운 등록 의자만 후보로 선택한다.
- 요청에는 `tableId`, `seatIndex`, `chairEntityName`을 전달한다.
- 서버는 요청자, map01, 거리, 구성 일치, 공석, 기존 착석 여부를 검증한다.
- 서버 예약 성공 후에만 기존 착석 애니메이션과 UI를 적용한다.
- X 재입력, 맵 이탈, 게임 종료의 기존 강제 일어서기 흐름에 레지스트리 해제를 연결한다.
- 동시 요청에도 한 명만 성공하도록 서버 예약을 먼저 확정한다.

### 🟡 4. 기본 무매칭과 테이블 격리 검증

- 기존 `전역 착석자 3명 → 3초 후 시작` 경로를 비활성화한다.
- map01 입장만으로 대기열, 강제 이동, 착석, 카운트다운이 발생하지 않게 한다.
- 같은 테이블 좌석만 한 그룹으로 조회되는지 확인한다.
- 서로 다른 테이블에 합계 3명이 앉아도 게임이 시작되지 않게 한다.
- 좌석 중복, 플레이어 중복, 잘못된 테이블·의자 조합의 서버 거부 테스트를 추가한다.
- 빌드·런타임 로그에서 오류 없이 예약과 해제가 예상 순서로 출력되는지 확인한다.

## 6. 예상 파일 접점

| 파일 | 변경 성격 |
|---|---|
| `RootDesk/MyDesk/LexioTableRegistry.mlua` | 신규 map01 테이블·좌석 상태 컴포넌트 |
| `RootDesk/MyDesk/LexioManualTestControls.mlua` | X 키 요청을 테이블 좌석 계약으로 전환 |
| `RootDesk/MyDesk/LexioSessionCoordinator.mlua` | 기존 전역 카운트다운 차단과 해제 연동 |
| `RootDesk/MyDesk/Models/MapObjects/LexioTable.model` | 필요 시 신규 테이블 모델 |
| `map/map01.map` | 테이블 3개, 의자 9개, 레지스트리 구성 |
| 기존 Lexio 테스트 또는 신규 테스트 컴포넌트 | 불변 조건과 테이블 격리 검증 |

구현 전 검색에서 실제 결합 위치가 다르면 기존 구조를 우선하되 위 책임 경계는 유지한다.

## 7. 구현 순서

1. map01과 기존 착석·세션 스크립트의 결합 지점을 확인한다.
2. 서버 레지스트리를 추가하고 순수 상태 테스트를 먼저 통과시킨다.
3. MapBuilder로 테이블과 의자를 배치하고 엔티티 구성을 맞춘다.
4. X 키 착석 요청을 새 계약으로 전환한다.
5. 기존 전역 게임 시작을 차단하고 해제 경로를 통합한다.
6. Maker refresh 후 빌드·런타임 검증을 수행한다.

## 8. 완료 기준

- map01에 구분되는 테이블 3개와 의자 9개가 있다.
- 입장 직후 매칭되지 않고 UI도 표시되지 않는다.
- 가까운 빈 의자에서 X를 누르면 해당 테이블·좌석에만 앉는다.
- 다시 X를 누르거나 맵을 나가면 좌석과 애니메이션이 모두 해제된다.
- 동일 좌석 중복 점유와 한 플레이어의 다중 착석이 불가능하다.
- 서로 다른 테이블에 총 3명이 앉아도 카운트다운이 시작되지 않는다.
- 빌드 오류가 없고 서버 로그로 예약·거부·해제를 확인할 수 있다.

## 9. 검증 경계

AI 검증은 구성·빌드 로그, 단일 클라이언트 착석·해제, 서버 상태 테스트까지 수행한다. 실제 동시 좌석 경쟁과 여러 테이블의 다중 플레이어 장면은 구현 후 사용자 플레이 테스트로 남긴다. 이 검증 전에는 Phase 1을 최종 완료로 판정하지 않는다.

## 10. Phase 2 인계

Phase 2는 레지스트리의 테이블별 플레이어 조회 결과만 사용해 같은 테이블의 정확히 3명을 대상으로 카운트다운과 게임 세션을 만든다. Phase 1에서는 좌석이나 UI가 게임 전역 상태를 직접 수정하는 새 우회 경로를 만들지 않는다.
