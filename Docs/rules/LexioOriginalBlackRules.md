# 렉시오 오리지널 블랙 최종 규칙 명세

## 1. 근거와 우선순위

이 문서의 규칙 근거 우선순위는 다음과 같다.

1. `LEXIO ORIGINAL BLACK Manual.pdf` 및 `LEXIO ORIGINAL BLACK Reference Card.pdf`
2. 프로젝트 요구사항(이 문서의 "프로젝트 확정 규칙")
3. 그 밖의 자료는 규칙 근거로 사용하지 않는다.

공식 설명서와 웹 자료 또는 일반적인 포커 규칙이 충돌하면 공식 설명서를 따른다. 공식 설명서에 없는 사항은 추론으로 확정하지 않고 `TODO`로 남긴다. 아래 페이지 표기는 PDF 파일의 1-based 페이지 번호다.

## 2. 구성과 게임 인원

- 3~5명이 플레이한다. (설명서 p.2)
- 타일은 해·달·별·구름 네 무늬별로 숫자 1~15가 하나씩 있어 총 60개다. (설명서 p.3)
- 레퍼런스 카드는 5장이다. 점수 칩은 1점·5점·10점 단위다. (설명서 p.3)
- 인원별 사용 숫자와 최초 배분량은 다음과 같다. (설명서 p.3)

| 인원 | 사용하는 숫자 | 1인당 타일 |
|---:|---|---:|
| 3 | 1~9 | 12 |
| 4 | 1~13 | 13 |
| 5 | 1~15 | 12 |

각 구성은 3인 `36=12×3`, 4인 `52=13×4`, 5인 `60=12×5`이므로 사용 범위의 타일을 모두 나누며 남는 타일이 없다.

## 3. 타일의 강약

### 3.1 숫자

일반적인 타일 강도는 `3 < 4 < ... < 15 < 1 < 2`다. `2`가 가장 높고 `3`이 가장 낮다. (설명서 p.2)

### 3.2 무늬

같은 숫자끼리는 `구름 < 별 < 달 < 해` 순으로 강하다. 따라서 해 2가 전체 최고 타일이고 구름 3이 전체 최저 타일이다. (설명서 p.2, p.6; 레퍼런스 카드 p.1)

구현 상수는 `구름=1, 별=2, 달=3, 해=4`로 둔다.

## 4. 제출 가능한 타일 수와 조합

- 한 번에 1장, 2장, 3장 또는 5장을 낼 수 있다. 4장은 낼 수 없다. (설명서 p.4, p.8)
- 1장: 싱글.
- 2장: 같은 숫자 2장인 페어.
- 3장: 같은 숫자 3장인 트리플.
- 5장 조합은 약한 순서부터 `스트레이트 < 플러시 < 풀하우스 < 포카드 < 스트레이트 플러시`다. (설명서 p.7; 레퍼런스 카드 p.1)
  - 스트레이트: 무늬와 무관하게 연속된 숫자 5장. (설명서 p.4)
  - 플러시: 숫자와 무관하게 같은 무늬 5장. (설명서 p.4)
  - 풀하우스: 같은 숫자 3장 + 다른 같은 숫자 2장. (설명서 p.4)
  - 포카드: 같은 숫자 4장 + 임의의 다른 1장. (설명서 p.4, p.8)
  - 스트레이트 플러시: 같은 무늬의 연속된 숫자 5장. (설명서 p.4)

## 5. 조합 비교

- 싱글은 숫자를 먼저 비교하고, 같으면 무늬를 비교한다. (설명서 p.6)
- 페어·트리플은 숫자를 먼저 비교한다. 숫자가 같으면 그 조합에 포함된 가장 강한 무늬를 비교한다. (설명서 p.6)
- 스트레이트는 먼저 숫자를 비교하고, 숫자가 같으면 무늬를 비교한다. 공식 표의 강도 예시는 `1,2,3,4,5`가 최강, `2,3,4,5,6`이 다음, `12,13,14,15,1`이 그 다음이다. (설명서 p.6)
- 플러시는 가장 큰 숫자부터 차례대로 비교하고, 다섯 숫자가 모두 같으면 무늬를 비교한다. (설명서 p.6)
- 풀하우스는 트리플을 이루는 숫자를 비교한다. (설명서 p.6)
- 포카드는 네 장을 이루는 숫자를 비교한다. (설명서 p.7)
- 스트레이트 플러시는 스트레이트와 같이 숫자를 먼저, 같으면 무늬를 비교한다. (설명서 p.7)
- 서로 다른 5장 조합은 위의 조합 등급을 먼저 비교한다. (설명서 p.7)
- 타일 수가 다른 제출끼리는 비교하지 않는다. 앞 제출과 같은 수의 타일만 낼 수 있다. (설명서 p.2, p.4)

### 5.1 숫자 `1`의 스트레이트 특례

`1`은 스트레이트에서 해당 인원 구성의 마지막 사용 숫자 다음 숫자로 사용할 수 있다. 3인에서는 9 다음의 10처럼, 4인에서는 13 다음의 14처럼, 5인에서는 15 다음의 16처럼 사용할 수 있다. `1`을 본래 강도 위치로 사용할 수도 있다. 마지막 사용 숫자 뒤로 이어질 수 있는 것은 `1`뿐이며 `..., 마지막 숫자, 1, 2`는 이어지지만 `..., 마지막 숫자, 2`는 이어지지 않는다. (설명서 p.7)

구현은 modulo 순환을 사용하지 않고 다음 목록만 스트레이트로 인정한다.

- `1,2,3,4,5` (최강)
- `2,3,4,5,6` (두 번째)
- `3,4,5,6,7`부터 인원별 마지막 일반 연속 조합까지
- `최대-3, 최대-2, 최대-1, 최대, 1` (`1`을 최대 숫자 다음 수로 쓰는 유일한 끝단 특례)

따라서 5인의 `12,13,14,15,1`은 유효하지만 `15,1,2,3,4`는 유효하지 않다. 3인과 4인도 각각 `6,7,8,9,1`, `10,11,12,13,1`까지만 같은 끝단 특례를 적용한다. 이 화이트리스트는 설명서 p.6의 강도 표와 p.7의 `1` 특례를 함께 만족한다.

## 6. 진행과 트릭

- 구름 3을 가진 플레이어가 최초 선이다. 최초 선 플레이어는 자신이 가진 타일 중 아무 합법 조합이나 낼 수 있으며, 첫 제출에 구름 3을 포함할 필요는 없다. (설명서 p.4의 선 결정 규칙 + 프로젝트 확정 해석)
- 다음 플레이어는 직전 제출과 같은 장수이면서 더 강한 타일 또는 조합만 낼 수 있다. (설명서 p.4)
- 더 강한 제출을 할 수 없거나 원하지 않으면 패스한다. (설명서 p.4)
- 한 플레이어의 제출 뒤 다른 모든 플레이어가 패스하면 그 플레이어가 선이 되어 원하는 합법 조합으로 새 트릭을 시작한다. (설명서 p.4)
- 누군가 모든 타일을 내면 게임을 끝내고 점수를 계산한다. (설명서 p.4)

### 프로젝트 확정 규칙

- 패스한 플레이어는 같은 트릭에 재참가할 수 없다.
- 직전 승자가 선으로 합법적인 새 제출을 하여 새 트릭이 시작되는 순간 모든 패스 상태를 초기화한다.

## 7. 종료 순위와 점수

- 5인 게임은 타일을 모두 낸 순서대로 1~5위를 정한다. (설명서 p.4)
- 기본 정산은 각 상위 순위자와 각 하위 순위자의 남은 타일 수 차이를 상위 순위자에게 이전하는 방식이다. 1위의 남은 수는 0이므로 모든 다른 플레이어의 남은 타일 수를 받는다. 마지막 순위자는 모든 상위 순위자에게 차이를 지급한다. 이 해석은 설명서의 순위별 문장과 두 계산 예시를 모두 만족한다. (설명서 p.5)
- 종료 시 `2` 타일이 남은 플레이어는 점수 계산용 남은 수를 배수 처리한다. `2` 한 장이면 ×2, 두 장이면 ×4, 세 장이면 ×8이다. (설명서 p.7)

### 프로젝트 확정 규칙

- 각 플레이어 점수는 `64`에서 시작하는 signed integer 장부로 관리한다.
- 실제 칩 보유량 제한은 적용하지 않으며 점수는 음수가 될 수 있다.
- 1점·5점·10점 칩은 UI 표시용 단위일 뿐 규칙 계산이나 지급 가능 금액을 제한하지 않는다.
- 한 게임의 정산 델타 합은 항상 0이어야 한다.

## 8. 구현 계약

- 타일 표현: `{ rank = 1..15, suit = 1..4 }`.
- 플레이어 수에 따라 허용 최대 숫자는 3인=9, 4인=13, 5인=15다.
- 제출 판정 결과는 유효 여부, 조합 종류, 장수, 비교 키를 제공한다.
- 현재 트릭 제출은 장수가 같고 비교 결과가 엄격히 클 때만 허용한다.
- 게임 진행 계층은 각 손패를 검사해 구름 3 보유자를 최초 선 플레이어로 결정한다. 첫 제출 조합에는 구름 3 포함 제약을 적용하지 않는다.
- 패스 상태인 플레이어의 같은 트릭 제출은 거부한다.
- 새 트릭은 현재 승자의 합법 제출로만 시작하고, 성공 시 패스 상태를 전부 초기화한다.
- 점수 장부는 정수만 받으며 초기값은 64다.

# 메이플 테마 점수 표시 요구사항 (향후 단계)

- 내부 점수 장부는 64에서 시작하는 signed integer를 그대로 유지한다.
- 실제 칩 부족은 적용하지 않고 음수 점수를 허용한다.
- 1점은 동메소 동전, 5점은 은메소 동전, 10점은 금메소 동전으로 표시한다.
- 동전은 UI 표시용이며 내부 점수 저장 단위가 아니다.
- 음수 점수는 UI에서 `메소 빚`으로 표시한다.
- 이번 GameSession 연결 단계에는 점수 필드, 정산 로직 또는 점수 UI를 추가하지 않는다. 한 판 진행 완성 후 별도 단계에서 연결한다.
